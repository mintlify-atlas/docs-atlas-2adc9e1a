Sparkling Water is published to the Maven repository as a Spark package under the coordinates `ai.h2o:sparkling-water-package_<scala_version>:<sw_version>`. You can reference it directly from any Spark installation using the `--packages` option — no separate Sparkling Water download is required.

<Note>
When using Spark packages, you only need a Spark installation. You do not need to download the Sparkling Water distribution archive.
</Note>

## Setup

<Steps>
  <Step title="Ensure SPARK_HOME is set">
    Confirm that the `SPARK_HOME` environment variable points to your Spark installation:

    ```bash
    echo $SPARK_HOME
    # e.g. /opt/spark
    ```
  </Step>
  <Step title="Identify the correct package coordinates">
    The package name follows the pattern:

    ```
    ai.h2o:sparkling-water-package_<scala_version>:<sw_version>
    ```

    For example, for Sparkling Water `3.36.1.3-1-3.3` built with Scala `2.12`:

    ```
    ai.h2o:sparkling-water-package_2.12:3.36.1.3-1-3.3
    ```

    Check the [H2O releases page](https://h2o-release.s3.amazonaws.com/sparkling-water/index.html) for available versions and their corresponding Scala and Spark versions.
  </Step>
  <Step title="Submit or launch with --packages">
    Pass the `--packages` argument to `spark-submit`, `spark-shell`, or `pyspark`. Spark will automatically resolve and download the package from Maven on first use.
  </Step>
</Steps>

## Launching an interactive shell

<CodeGroup>

```bash Scala shell
$SPARK_HOME/bin/spark-shell \
  --packages ai.h2o:sparkling-water-package_2.12:<sw_version>
```

```bash PySpark shell
$SPARK_HOME/bin/pyspark \
  --packages ai.h2o:sparkling-water-package_2.12:<sw_version>
```

</CodeGroup>

## Submitting a job

### Local mode

Local mode runs everything in a single JVM process. Useful for development and testing.

<CodeGroup>

```bash Scala (spark-submit)
$SPARK_HOME/bin/spark-submit \
  --packages ai.h2o:sparkling-water-package_2.12:<sw_version> \
  --master local[*] \
  --class ai.h2o.sparkling.examples.CraigslistJobTitlesStreamingApp \
  /dev/null
```

```bash PySpark (spark-submit)
$SPARK_HOME/bin/spark-submit \
  --packages ai.h2o:sparkling-water-package_2.12:<sw_version> \
  --master local[*] \
  my_pysparkling_script.py
```

</CodeGroup>

### YARN mode

<CodeGroup>

```bash Scala — YARN client mode
$SPARK_HOME/bin/spark-submit \
  --packages ai.h2o:sparkling-water-package_2.12:<sw_version> \
  --master yarn \
  --deploy-mode client \
  --class ai.h2o.sparkling.examples.CraigslistJobTitlesStreamingApp \
  /dev/null
```

```bash Scala — YARN cluster mode
$SPARK_HOME/bin/spark-submit \
  --packages ai.h2o:sparkling-water-package_2.12:<sw_version> \
  --master yarn \
  --deploy-mode cluster \
  --class ai.h2o.sparkling.examples.CraigslistJobTitlesStreamingApp \
  /dev/null
```

```bash PySpark — YARN client mode
$SPARK_HOME/bin/spark-submit \
  --packages ai.h2o:sparkling-water-package_2.12:<sw_version> \
  --master yarn \
  --deploy-mode client \
  my_pysparkling_script.py
```

</CodeGroup>

### Kubernetes mode

On Kubernetes, Sparkling Water requires the `spark.scheduler.minRegisteredResourcesRatio=1` configuration and that dynamic allocation is disabled.

<CodeGroup>

```bash Scala — Kubernetes cluster mode
$SPARK_HOME/bin/spark-submit \
  --packages ai.h2o:sparkling-water-package_2.12:<sw_version> \
  --master "k8s://KUBERNETES_ENDPOINT" \
  --deploy-mode cluster \
  --conf spark.scheduler.minRegisteredResourcesRatio=1 \
  --conf spark.kubernetes.container.image=h2oai/sparkling-water-scala:<sw_version> \
  --conf spark.executor.instances=3 \
  --conf spark.driver.host=sparkling-water-app \
  --conf spark.kubernetes.driver.pod.name=sparkling-water-app \
  --class ai.h2o.sparkling.KubernetesTest \
  local:///opt/sparkling-water/tests/kubernetesTest.jar
```

```bash PySpark — Kubernetes cluster mode
$SPARK_HOME/bin/spark-submit \
  --packages ai.h2o:sparkling-water-package_2.12:<sw_version> \
  --master "k8s://KUBERNETES_ENDPOINT" \
  --deploy-mode cluster \
  --conf spark.scheduler.minRegisteredResourcesRatio=1 \
  --conf spark.kubernetes.container.image=h2oai/sparkling-water-python:<sw_version> \
  --conf spark.executor.instances=3 \
  --conf spark.driver.host=sparkling-water-app \
  --conf spark.kubernetes.driver.pod.name=sparkling-water-app \
  local:///opt/sparkling-water/tests/initTest.py
```

</CodeGroup>

<Note>
For Kubernetes, Sparkling Water supports versions Spark 2.4 and later. Run `kubectl cluster-info` to obtain the Kubernetes master URL to use as `KUBERNETES_ENDPOINT`. Ports `54321` and `54322` must be accessible between pods for H2O cluster communication.
</Note>

## Using --jars instead of --packages

If you have already downloaded the Sparkling Water assembly JAR, you can add it to the classpath directly using `--jars` instead of resolving it from Maven:

```bash
$SPARK_HOME/bin/spark-submit \
  --jars /path/to/sparkling-water-assembly_2.12-<sw_version>-all.jar \
  --class ai.h2o.sparkling.examples.CraigslistJobTitlesStreamingApp \
  /dev/null
```

The assembly JAR is located in the `jars/` directory of the Sparkling Water distribution archive.
